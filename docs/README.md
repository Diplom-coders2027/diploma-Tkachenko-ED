# Требования к оформлению проектной документации (Диплом)

В данной папке размещаются исходные материалы пояснительной записки (ПЗ), диаграммы, иллюстрации и презентация к защите дипломного проекта для студентов **3 и 5 курса** курсов программирования.

---

## 📐 1. Основные стандарты оформления (по ГОСТ 7.32 / ГОСТ 2.105)

При оформлении текста выпускного проекта рекомендуется придерживаться следующих типовых параметров:

| Параметр | Требование |
| :--- | :--- |
| **Гарнитура (шрифт)** | Times New Roman (или PT Astra Serif / Liberation Serif) |
| **Кегль (размер шрифта)** | 14 пт (в таблицах, сносках допускается 10–12 пт) |
| **Межстрочный интервал** | Полуторный (1.5) |
| **Цвет шрифта** | Черный |
| **Поля страницы** | Левое: **30 мм**, Правое: **10–15 мм**, Верхнее: **20 мм**, Нижнее: **20 мм** |
| **Абзацный отступ (красная строка)** | **1.25 см** (одинаковый по всему тексту) |
| **Выравнивание текста** | По ширине страницы (с включенной автоматической расстановкой переносов) |
| **Нумерация страниц** | Сквозная, арабскими цифрами, по центру внизу страницы (без точки). На титульном листе номер **не ставится**, но включается в общую нумерацию. |

## 📑 2. Структура пояснительной записки

1. **Титульный лист** (тема проекта, студент, 3 или 5 курс, группа, преподаватель, учебный год 2026 / 2027)
2. **Техническое задание (ТЗ) на проект** (согласованное с преподавателем)
3. **Аннотация / Резюме проекта** (краткая выжимка: цель разработки, стек, ключевой функционал)
4. **Содержание** (автоматически собираемое оглавление)
5. **Перечень сокращений и условных обозначений** (при необходимости)
6. **Введение**
   - Актуальность разработки программного продукта
   - Проблема и целевая аудитория
   - Цель и задачи проекта
   - Ожидаемый практический результат
7. **Раздел 1. Аналитическая часть**
   - Анализ предметной области и пользовательских сценариев
   - Сравнительный обзор существующих аналогов и решений (сводная таблица)
   - Функциональные и нефункциональные требования к системе
8. **Раздел 2. Архитектура и проектирование**
   - Общая архитектура системы (C4 Model / диаграмма компонентов)
   - Модель данных и проектирование БД (ER-диаграмма, описание таблиц/коллекций, индексов)
   - Проектирование API и взаимодействия сервисов (Sequence диаграммы, спецификация OpenAPI)
   - Пользовательский интерфейс (Wireframes / макеты экранов)
9. **Раздел 3. Практическая реализация**
   - Обоснование выбора технологического стека, библиотек и фреймворков
   - Описание реализации ключевых модулей и алгоритмов
   - Механизмы аутентификации, авторизации и безопасности
   - Развертывание и контейнеризация (Docker, Docker Compose, CI/CD)
10. **Раздел 4. Тестирование и верификация**
    - Методология тестирования (Unit, Integration, E2E)
    - Результаты тестирования и процент покрытия кода
    - Проверка надежности и производительности
11. **Заключение** (итоги выполнения поставленных задач, перспективы развития проекта)
12. **Список использованных источников и документации** (официальная документация, статьи, книги)
13. **Приложения** (листинги ключевого кода, подробные схемы, примеры конфигураций)

## 🖼 3. Правила оформления элементов текста

### Рисунки (схемы, диаграммы, графики)
- Все иллюстрации должны быть четкими, читаемыми и выполнены в векторном формате (SVG, PDF) или растровом высоком разрешении (PNG >= 300 dpi).
- На **каждый** рисунок в тексте **обязательно** должна быть прямая ссылка: `...как показано на рисунке 2.1...`. Рисунок помещается сразу после первого упоминания в тексте или на следующей странице.
- Подрисуночная подпись располагается **по центру под рисунком**:
  > *Рисунок 2.1 — Архитектурная схема взаимодействия микросервисов*

### Таблицы
- На каждую таблицу должна быть ссылка в тексте: `...приведены в таблице 1.2.`.
- Заголовок таблицы пишется слева над таблицей:
  > *Таблица 1.2 — Сравнительный анализ существующих решений*

### Листинги программного кода
- Короткие фрагменты кода (до 15–20 строк) допускается размещать в основном тексте с использованием моноширинного шрифта (Courier New / Consolas, 10–11 пт) и подписью:
  > *Листинг 3.1 — Реализация алгоритма вычисления ранга*
- Полные исходные тексты выносятся в **Приложения**.

## 🛠 4. Рекомендуемые форматы хранения в `docs/`

Вы можете выбрать удобный инструмент для написания записки:

1. **Markdown (Рекомендуется для Git):**
   - Быстрое написание глав с возможностью экспорта в DOCX / PDF через Pandoc. Полный контроль версий и удобный diff в Pull Request.
2. **LaTeX / Typst:**
   - Для идеальной типографики и автоматической нумерации/библиографии по ГОСТ.
3. **Microsoft Word / LibreOffice Writer (`.docx`):**
   - Допускается, исходный `.docx` файл сохраняется в папке `docs/`. Временные файлы Word (`~$*`) автоматически игнорируются через `.gitignore`.

### Хранение диаграмм
- Исходники диаграмм храните в редактируемом виде рядом с изображениями:
  - `docs/diagrams/*.puml` (PlantUML)
  - `docs/diagrams/*.drawio` (draw.io / diagrams.net)
  - `docs/diagrams/*.mmd` (Mermaid)
